# ADR S1: 상품 목록 무한 스크롤 — 가상화 + 쿼리 캐시 + SSR

**날짜**: 2026-11-27
**상태**: 완료 (SC-004 측정 Checkpoint B 대기)
**스펙**: specs/001-product-list/spec.md
**커밋**: c646352

---

## 문제

상품 수천 개를 무한 스크롤로 내리면 DOM 요소가 쌓여, 저사양 기준 환경(중저가 안드로이드폰)에서 스크롤이 끊기고 메모리가 계속 늘어난다. 이를 가상화로 풀면 이번엔 상세 페이지에서 뒤로가기 했을 때 목록 위치가 사라지고, 검색 엔진이 읽을 첫 화면이 비는 부작용이 생긴다.

설계서 K1 (docs/design-decisions.md) "무한 스크롤 목록의 성능과 탐색 흐름"에 대한 구현 결정 기록.

---

## 대안 비교

### 원인 1 — DOM 요소 누적으로 스크롤 끊김·메모리 증가

| 대안 | 장점 | 한계 |
| --- | --- | --- |
| 무한 스크롤 그대로 | 구현 단순 | 저사양 기기에서 끊김·메모리 증가 |
| 페이지네이션으로 회귀 | 요소 수 일정 | 탐색 흐름이 끊기고 모바일 커머스 관행과 다름 |
| CSS content-visibility | 코드 변경 최소 | 요소 자체는 남아 메모리는 그대로 |
| **목록 가상화 ← 선택** | 보이는 부분만 그려 요소 수 일정 | 스크롤 복원·검색 노출을 따로 처리해야 함 |

### 원인 2 — 가상화 이후 뒤로가기 위치 소실·첫 화면 공백

| 대안 | 장점 | 한계 |
| --- | --- | --- |
| 브라우저 기본 스크롤 복원 | 별도 작업 없음 | 데이터를 다시 불러오고 가상화 목록에선 위치가 어긋남 |
| 상세를 모달로 띄우기 | 목록이 그대로 유지 | 상세 직접 진입·공유·검색 노출 처리가 복잡 |
| 목록 데이터를 브라우저 저장소에 저장 | 확실히 복원 | 저장 데이터가 크고 오래된 가격·재고를 보여줄 위험 |
| **쿼리 캐시 유지 + 스크롤 위치 저장 + 첫 화면 SSR ← 선택** | 다시 불러오지 않고 위치 그대로, 검색 노출도 확보 | 캐시 유지 시간 설계 필요 |

---

## 선택한 방식

**가상화(@tanstack/react-virtual v3) + TanStack Query v5 무한 쿼리 + sessionStorage 스크롤 위치 + Next.js Server Component SSR**

### 세부 구성

| 역할 | 선택 | 값 |
| --- | --- | --- |
| 가상화 | `@tanstack/react-virtual` v3 | `estimateSize: 104px`, `overscan: 2` |
| 무한 쿼리 캐시 | `@tanstack/react-query` v5 | `staleTime: 300_000ms`, `gcTime: 300_000ms` (5분) |
| 스크롤 위치 저장소 | `sessionStorage` | `{ savedAt, itemIndex, scrollTop }` |
| 만료 시간 | 5분 | `savedAt` 기준 300_000ms 초과 시 배너 표시 |
| 페이지당 상품 수 | 20개 | Route Handler `limit=20` |
| SSR | Next.js Server Component | `prefetchInfiniteQuery` 1페이지(20개), graceful fallback |
| 오류 재시도 | 사용자 수동 | `retry: 0`, "다시 시도" 버튼 |

### 선택 이유

1. **가상화 선택**: 저사양 기기에서 메모리까지 줄이려면 요소 자체를 줄여야 한다. `content-visibility`는 요소가 DOM에 남아 메모리를 차지하므로 한계가 있다.
2. **상세 모달 기각**: 커머스에서 상세 페이지의 직접 진입·공유·검색 노출이 중요해 URL 기반 페이지 이동이 필요하다.
3. **쿼리 캐시로 위치 복원**: 이미 불러온 데이터를 TanStack Query가 메모리에 보관하므로 뒤로가기 시 재요청 없이 복원할 수 있다. sessionStorage에는 최소한의 위치 정보만 저장해 오래된 가격·재고 노출 위험을 줄인다.
4. **SSR + HydrationBoundary**: Slow 4G에서 JS 도착 전 첫 화면이 비지 않고 상품이 보인다. TanStack Query의 dehydrate/hydrate 패턴으로 클라이언트 재요청 없이 서버 데이터를 이어받는다.
