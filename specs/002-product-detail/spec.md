# Feature Specification: 즉시 반응하는 상품 상세

**Feature Branch**: `002-product-detail`
**Spec ID**: S2
**Created**: 2026-11-27
**Status**: Draft
**기능 우선순위**: P0
**릴리스 단계**: 1차 배포 (세 번째, S1 다음)
**Input**: PRD 정리본 2·3·6·7장 / docs/spec-guide.md S2 섹션 / docs/design-decisions.md K3·B3·B4 / specs/001-product-list/spec.md

중저가 휴대폰으로 쇼핑하는 사용자가 상품 상세 화면에 도착하는 순간 옵션과 구매 버튼이 바로 작동하게 한다. 화면이 보이는데 JS가 실행되기 전까지 버튼이 눌리지 않는 빈 시간을 없앤다.

## 범위

| 포함 | 범위 밖 |
| --- | --- |
| 상품 상세 화면: 상품 정보, 대표 이미지, 긴 상세 이미지(원본 그대로) | 긴 상세 이미지 분할·최적화 (S4) |
| 옵션 그룹별 선택, 품절 옵션 표시(선택 불가) | 대표 이미지 LCP·CLS 최적화 (PRD 5장 "MVP 밖 개선 과제", 설계서 K6) |
| 구매·장바구니 버튼 UI (실제 동작은 S3) | 저사양 기기 옵션 반응 속도 추가 최적화 (PRD 5장 "MVP 밖 개선 과제", 설계서 K4) |
| 목록(S1)에서 상세로 이동, 상세에서 목록으로 돌아가기 | 장바구니·주문서·결제 흐름 (S3) |

> **메모**: 이 스펙에서 긴 상세 이미지는 최적화 없는 원본 그대로 표시한다. 이 상태가 S4의 개선 전 비교 기준이 된다. 대표 이미지의 LCP·CLS 개선도 범위 밖이다(설계서 K6).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 상세 화면이 보이는 순간 옵션과 버튼이 바로 작동 (필수)

사용자가 상품 목록에서 상품 카드를 눌러 상세 화면으로 이동하면, 화면이 나타나는 순간부터 옵션 선택과 구매·장바구니 버튼이 작동한다. JS 실행이 끝나기를 기다리는 빈 시간이 없어, 옵션을 눌렀는데 반응이 없어 여러 번 누르는 일이 생기지 않는다.

**Why this priority**: PRD 1장 상세 단계의 핵심 문제다. 저사양 기기에서 화면이 보이지만 아무것도 작동하지 않는 빈 시간이 길어, 사용자가 옵션을 반복해서 누르게 된다. 이 빈 시간을 없애는 것이 S2의 존재 이유다.

**Independent Test**: 기준 환경(저사양 모바일 프리셋 + Slow 4G, 프로덕션 빌드)에서 상세 페이지 메인 스레드 점유 시간(TBT)을 측정한다.

**Acceptance Scenarios**:

1. **Given** 상품 목록에서 상품 카드, **When** 카드를 누르면, **Then** 그 상품의 상세 화면으로 이동한다.
2. **Given** 상세 화면이 로드되는 중, **When** 화면이 보이기 시작하면, **Then** 옵션 버튼과 구매·장바구니 버튼이 즉시 작동한다.
3. **Given** 기준 환경에서 상세 페이지 로드, **Then** 메인 스레드 점유 시간(TBT)이 200ms 이하다.
4. **Given** 상세 화면에서 옵션을 클릭할 때, **Then** 200ms(INP 기준) 이내에 선택된 상태가 반영된다.

---

### User Story 2 — 옵션 그룹별 선택과 품절 표시 (필수)

사용자가 상품 상세 화면에서 색상·사이즈 같은 옵션 그룹별로 원하는 옵션을 선택한다. 품절 옵션은 화면에 표시되지만 선택할 수 없고, 선택 불가 상태가 시각적으로 구분된다. 모든 그룹의 옵션을 선택하면 구매·장바구니 버튼이 활성화된다.

**Why this priority**: 옵션 선택은 구매 직전 단계다. 품절 옵션을 눌렀다가 오류가 나는 것보다 처음부터 선택 불가로 표시하는 것이 사용자 경험의 핵심이다. 모든 옵션이 선택되기 전까지 버튼이 비활성화되어야 실수로 미선택 상태로 구매하는 일을 막는다.

**Independent Test**: 옵션 그룹이 2개 이상이고 일부 옵션이 품절인 상품 상세에서, 그룹별 옵션 선택 → 버튼 활성화 / 품절 옵션 선택 차단 흐름을 E2E로 확인한다.

**Acceptance Scenarios**:

1. **Given** 옵션 그룹이 있는 상품 상세, **When** 각 그룹에서 옵션을 하나씩 선택하면, **Then** 선택된 옵션이 시각적으로 표시된다.
2. **Given** 품절 옵션이 있는 상품 상세, **Then** 품절 옵션은 선택 불가 상태로 시각적으로 구분되어 표시된다.
3. **Given** 품절 옵션, **When** 클릭하면, **Then** 선택되지 않는다.
4. **Given** 옵션 그룹이 2개 이상, **When** 일부 그룹만 선택한 상태, **Then** 구매·장바구니 버튼이 비활성화 상태를 유지한다.
5. **Given** 모든 그룹의 옵션을 선택한 상태, **Then** 구매·장바구니 버튼이 활성화된다.
6. **Given** 키보드만 쓰는 사용자, **When** 키보드로 옵션을 탐색하면, **Then** 모든 옵션 그룹의 선택 가능한 옵션을 선택할 수 있다.
7. **Given** 스크린리더 사용자, **When** 품절 옵션에 접근하면, **Then** 선택 불가 상태가 읽힌다.

---

### User Story 3 — 상세 화면의 상품 정보와 이미지 확인 (필수)

사용자가 상품 상세 화면에서 상품명·가격·상세 설명, 대표 이미지, 긴 상세 이미지를 확인한다. 360px 너비 화면에서도 가로 스크롤 없이 모든 정보를 볼 수 있다.

**Why this priority**: 상품 정보가 올바르게 표시되는 것은 모든 상세 화면 기능의 전제다. 모바일 최소 너비(360px)에서 가로 스크롤이 생기면 핵심 사용자가 콘텐츠를 볼 수 없다.

**Independent Test**: 360px 뷰포트에서 상세 페이지를 열고 가로 스크롤바 없이 모든 정보가 표시되는지 E2E로 확인한다.

**Acceptance Scenarios**:

1. **Given** 상품 상세 URL로 접근, **When** 화면이 로드되면, **Then** 상품명·가격·대표 이미지가 표시된다.
2. **Given** 긴 상세 이미지가 있는 상품, **When** 아래로 스크롤하면, **Then** 긴 상세 이미지가 표시된다.
3. **Given** 360px 너비 화면, **Then** 가로 스크롤바가 나타나지 않는다.
4. **Given** 스크린리더 사용자, **When** 상세 화면에 접근하면, **Then** 상품명·가격과 대표 이미지의 대체 텍스트가 읽힌다.

---

### User Story 4 — 구매·장바구니 버튼 (보조)

사용자가 옵션을 모두 선택하면 구매·장바구니 버튼이 활성화된다. 이번 스펙에서는 버튼의 실제 주문·장바구니 담기 동작은 구현되지 않는다(S3에서 구현). 버튼을 눌렀을 때 오류가 나거나 의도치 않은 동작은 생기지 않는다.

**Why this priority**: 버튼 UI는 S3 구현의 기반이다. 이번 스펙에서 완성된 동작이 필요하지 않지만, 올바른 활성화/비활성화 상태를 화면에 표시해야 한다.

**Independent Test**: 옵션을 모두 선택하면 버튼이 활성화되고, 미선택 시 비활성화 상태를 유지하는지 E2E로 확인한다.

**Acceptance Scenarios**:

1. **Given** 옵션이 필요한 상품에서 옵션 미선택, **Then** 구매·장바구니 버튼이 비활성화 상태로 표시된다.
2. **Given** 모든 필요한 옵션을 선택한 상태, **Then** 구매·장바구니 버튼이 활성화 상태로 표시된다.
3. **Given** 활성화된 버튼, **When** 누르면, **Then** 의도치 않은 동작이 발생하지 않는다 (S3 연결 전).
4. **Given** 모든 옵션이 품절인 상품, **Then** 구매·장바구니 버튼이 비활성화 상태를 유지하고 품절 안내가 표시된다.
5. **Given** 스크린리더 사용자, **When** 버튼에 접근하면, **Then** 버튼의 활성화/비활성화 상태가 읽힌다.

---

### User Story 5 — 목록에서 상세로, 상세에서 목록으로 이동 (필수)

사용자가 상품 목록에서 카드를 눌러 상세로 이동하고, 상세에서 뒤로가기를 누르면 S1에서 정의한 스크롤 위치로 목록이 복원된다.

**Why this priority**: 목록과 상세 사이의 이동은 모바일 커머스의 핵심 탐색 흐름이다. S2 구현이 S1의 스크롤 위치 복원(SC-002)을 망가뜨리지 않아야 한다.

**Independent Test**: 목록 → 상세 → 뒤로가기 E2E에서 S1 SC-002(50번째 상품 위치 복원, 재요청 0건)가 여전히 통과하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 상품 목록, **When** 상품 카드를 누르면, **Then** 그 상품의 상세 화면으로 이동한다.
2. **Given** 상세 화면, **When** 뒤로가기를 하면, **Then** S1에서 정의한 스크롤 위치로 목록이 복원된다.
3. **Given** 상세 화면 URL을 직접 입력해 접근, **When** 화면이 로드되면, **Then** 해당 상품의 상세 정보가 표시된다.
4. **Given** 키보드만 쓰는 사용자, **When** 상세에서 뒤로가기를 하면, **Then** S1에서 정의한 카드 포커스 복원이 작동한다.

---

### Edge Cases

- **옵션이 없는 상품**: 옵션 그룹이 없는 상품은 옵션 선택 영역 없이 구매·장바구니 버튼이 활성화 상태로 표시된다.
- **모든 옵션이 품절인 상품**: 구매·장바구니 버튼이 비활성화 상태로 고정되고, 품절 안내가 표시된다.
- **대표 이미지 로딩 실패**: 이미지 대신 대체 텍스트가 표시되고, 나머지 상세 정보는 정상적으로 보인다.
- **긴 상세 이미지가 없는 상품**: 긴 상세 이미지 영역이 표시되지 않는다. 나머지 상세 정보는 정상적으로 보인다.
- **상품 ID가 없거나 유효하지 않은 URL**: 상품을 찾을 수 없다는 안내와 목록으로 돌아가는 수단을 보여준다.
- **상세 화면 로드 실패**: 상품 데이터를 불러오지 못하면 오류 안내와 다시 시도 수단을 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

**상세 화면 표시**

- **FR-001**: 상품 상세 화면은 상품명·가격·대표 이미지를 표시해야 한다(MUST).
- **FR-002**: 긴 상세 이미지가 있는 상품은 상세 화면에 긴 상세 이미지를 표시해야 한다(MUST). S2에서는 원본 이미지 그대로 표시한다(분할·최적화는 S4).
- **FR-003**: 360px 너비 화면에서 가로 스크롤 없이 모든 상세 정보를 볼 수 있어야 한다(MUST).
- **FR-004**: 상품 ID가 없거나 유효하지 않은 URL로 접근하면 상품을 찾을 수 없다는 안내와 목록으로 돌아가는 수단을 표시해야 한다(MUST).
- **FR-005**: 상품 데이터 로드에 실패하면 오류 안내와 다시 시도 수단을 표시해야 한다(MUST).

**반응 속도**

- **FR-006**: 상세 화면이 보이는 순간부터 옵션 선택과 구매·장바구니 버튼이 작동해야 한다(MUST). 메인 스레드 점유 시간(TBT)이 200ms를 초과하지 않아야 한다(MUST).
- **FR-007**: 옵션 클릭에서 선택 상태 반영까지 200ms(INP 기준) 이내여야 한다(MUST).

**옵션 선택**

- **FR-008**: 옵션 그룹이 있는 상품은 각 그룹별로 옵션을 선택할 수 있어야 한다(MUST).
- **FR-009**: 품절 옵션은 화면에 표시하되 선택할 수 없어야 한다(MUST). 품절 상태를 시각적으로 구분해야 한다(MUST).
- **FR-010**: 옵션 그룹이 있는 상품에서 모든 그룹의 옵션이 선택되면 구매·장바구니 버튼이 활성화되어야 한다(MUST).
- **FR-011**: 모든 옵션이 품절인 상품은 구매·장바구니 버튼이 비활성화 상태를 유지하고 품절 안내를 표시해야 한다(MUST).
- **FR-012**: 옵션이 없는 상품은 옵션 선택 영역 없이 구매·장바구니 버튼이 활성화 상태로 표시되어야 한다(MUST).

**구매·장바구니 버튼**

- **FR-013**: 구매 버튼과 장바구니 버튼은 상세 화면에 표시되어야 한다(MUST). 실제 주문·장바구니 담기 동작은 S3에서 구현된다.
- **FR-014**: 비활성화 상태의 버튼은 누르더라도 의도치 않은 동작이 생기지 않아야 한다(MUST NOT).

**탐색**

- **FR-015**: 상품 목록(S1)에서 상품 카드를 누르면 그 상품의 상세 화면으로 이동해야 한다(MUST).
- **FR-016**: 상세 화면에서 뒤로가기를 하면 S1에서 정의한 스크롤 위치 복원이 올바르게 작동해야 한다(MUST).
- **FR-017**: 상세 화면 URL을 직접 입력해도 해당 상품의 정보가 표시되어야 한다(MUST).

**접근성** (Constitution 품질 게이트)

- **FR-018**: 키보드만으로 상품 상세 탐색, 옵션 선택, 구매·장바구니 버튼 접근이 가능해야 한다(MUST).
- **FR-019**: 대표 이미지와 긴 상세 이미지는 스크린리더가 읽을 수 있는 대체 텍스트를 가져야 한다(MUST).
- **FR-020**: 품절 옵션의 선택 불가 상태는 스크린리더에서도 인식할 수 있어야 한다(MUST).
- **FR-021**: 버튼의 비활성화 상태는 스크린리더에서도 인식할 수 있어야 한다(MUST).

### Key Entities

- **상품 상세 화면**: 상품 정보·이미지·옵션·버튼을 포함하는 단일 화면. S1 목록 카드에서 진입하거나 URL 직접 입력으로 접근한다
- **상품**: 상품명·가격·대표 이미지·긴 상세 이미지·옵션 그룹을 가진다. S0 시드 데이터에서 불러온다
- **옵션 그룹**: 하나의 상품에 여러 그룹이 있을 수 있다 (예: 색상·사이즈). 각 그룹에는 선택 가능한 옵션과 품절 옵션이 함께 있을 수 있다
- **옵션**: 옵션 그룹 내의 단일 선택 항목. 재고가 없으면 품절 상태다
- **구매·장바구니 버튼**: 모든 필요한 옵션이 선택되면 활성화된다. 실제 동작은 S3에서 연결된다

## Success Criteria *(mandatory)*

### Measurable Outcomes

**PRD 6장 성공 기준**

- **SC-001** (TBT): 기준 환경(저사양 모바일 프리셋 + Slow 4G, 프로덕션 빌드)에서 상세 페이지 메인 스레드 점유 시간(TBT)이 200ms 이하다. 3회 측정 중앙값으로 판단한다.
  - *측정 시나리오*: 프로덕션 빌드에서 상세 페이지 Lighthouse 실행. 3회 측정, 중앙값과 원값(3회 모두) 기록.
  - *달성하지 못할 경우*: 측정값과 원인을 기록하고, 대안 비교 측정은 1차 배포 후 선택적으로 한다.

- **SC-002** (INP): 기준 환경에서 옵션 클릭 시나리오의 INP가 200ms 이하다. 3회 측정 중앙값으로 판단한다.
  - *측정 시나리오*: 프로덕션 빌드에서 옵션을 클릭하고 선택 상태가 반영되기까지의 INP를 성능 패널로 측정. 3회 측정, 중앙값과 원값 기록.

- **SC-003** (JS 전송 크기): 상세 페이지 JS 전송 크기를 기록한다. 목표 수치 대신 기록을 남기며, 이후 최적화 비교의 기준이 된다.
  - *측정 시나리오*: 프로덕션 빌드에서 상세 페이지 로드 시 JS 번들 크기를 네트워크 패널에서 확인.

**Constitution 품질 게이트**

- **SC-004** (레이아웃): 360px 너비 화면에서 상세 페이지 가로 스크롤이 없다.
  - *측정 시나리오*: 360px 뷰포트 E2E에서 가로 스크롤바 존재 여부 확인.

- **SC-005** (접근성): 키보드만으로 목록 → 상세 진입 → 옵션 선택 → 구매 버튼 접근 흐름을 완료할 수 있다. 상세 페이지 자동 접근성 검사(axe) 심각·치명 등급 위반 0건.

- **SC-006** (기본 검사): 타입 검사·단위 테스트·E2E가 CI에서 모두 통과한다.

- **SC-007** (S1 회귀 없음): S2 구현 후에도 S1의 SC-002(50번째 상품 상세 후 뒤로가기 위치 복원, 재요청 0건)가 E2E에서 통과한다.

## Assumptions

- 상품 데이터는 S0에서 생성한 시드 데이터를 사용한다. 상품 상세 조회 API(단건 조회)는 plan에서 설계한다.
- 옵션 그룹 간 의존 관계(예: 색상 선택 후에만 사이즈 표시)는 없다고 가정한다. 각 그룹은 독립적으로 선택한다.
- 긴 상세 이미지는 원본 그대로 표시한다. 최적화(분할·포맷 변환)는 S4에서 한다. 이 상태가 S4 개선 전 비교 기준이 된다.
- 품절 상품 상세에는 진입할 수 있으나, 모든 옵션이 품절이면 구매·장바구니 버튼이 비활성화 상태로 고정된다 (S1 Assumptions에서 S2에서 정하기로 한 항목).
- 구매·장바구니 버튼의 S3 연결 방식(라우팅, 전달 데이터)은 S3 spec에서 정한다. S2에서는 버튼의 활성화/비활성화 상태와 선택된 옵션 정보 보관만 담당한다.
- 모바일 크롬 우선으로 만들고, iOS 사파리는 핵심 흐름(상세 진입·옵션 선택)만 동작 확인한다.
- 성능 예산(SC-001 TBT 측정 중앙값 + 10%, SC-002 INP 측정 중앙값 + 10%)은 측정 완료 후 CI에 등록한다. 측정 전 PR은 측정값만 남기고 실패시키지 않는다 (Constitution 품질 게이트).
